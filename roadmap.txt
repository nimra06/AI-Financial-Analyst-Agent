AI FINANCIAL ANALYST AGENT — ROADMAP
=====================================

GOAL
----
Build a portfolio-grade, enterprise-feeling product: upload financial data →
deterministic analytics → AI insights with explainability → chat → forecasts →
reports. Worth doing fully: strong stack, testable core, clear path from MVP
to polished SaaS-style demo.


================================================================================
FINAL PRODUCT (PHASED — DO NOT BUILD ALL AT ONCE)
================================================================================

PHASE A — MVP (Steps 1–3)
  Upload: CSV, XLSX (one canonical schema first; see DATA CONTRACT below)
  Output:  KPI dashboard, metric-backed AI summary, tool-based chat

PHASE B — Advanced analytics (Steps 4–5)
  Forecasting, anomaly detection, confidence intervals

PHASE C — Enterprise polish (Steps 6–8)
  PDF/HTML reports, session history, UI upgrade, optional auth

PHASE D — Extended ingestion (later)
  PDF P&L, bank statements (OCR + table extraction — separate mini-project)

User asks:
  "Why did profits drop in March?"

AI answers with:
  charts, insights tied to computed numbers, possible reasons, recommendations

Every AI claim must trace back to precomputed metrics (no hallucinated %).


================================================================================
CORE PRINCIPLES (NON-NEGOTIABLE)
================================================================================

1. SCHEMA FIRST
   Validate uploads before charts or AI. Show preview + clear errors.

2. METRICS BEFORE LLM
   pandas computes KPIs, MoM, top expenses, flags → JSON snapshot → LLM
   only interprets structured CONTEXT. Prompt rule: cite only numbers in CONTEXT.

3. TOOL-BASED CHAT (NOT GENERIC RAG ON CSV ROWS)
   Chat uses functions over the dataset: get_kpi, compare_months, top_expenses,
   forecast_series. Vector RAG reserved for PDFs / uploaded narrative docs.

4. ONE HAPPY PATH FIRST
   Ship one sample template (CSV + column definitions in README) before
   supporting every file type.

5. TRUST & DISCLAIMERS
   UI + README: analysis/demo only, not financial advice. Prefer local/session
   processing; no bank credentials in v1.


================================================================================
TECH STACK (GOOD, MODERN, WORTH THE EFFORT)
================================================================================

LANGUAGE & RUNTIME
  Python 3.11+

FRONTEND (TWO-STAGE — BOTH ARE WORTH IT)
  Stage 1 (Steps 1–5): Streamlit — fast MVP, great for demos
  Stage 2 (Step 7+):    Next.js 14+ (App Router) + Tailwind + shadcn/ui
                        Professional UI, reuse FastAPI backend

BACKEND API
  FastAPI — add when chat/sessions need REST (Step 3); shared logic lives in
  analytics/ modules callable from Streamlit OR FastAPI

DATA & VALIDATION
  pandas, numpy
  pydantic — upload schemas, API models, LLM structured output
  openpyxl — Excel

ANALYTICS & ML
  scikit-learn — Isolation Forest (Step 5)
  statsmodels or scipy — simple statistical anomalies (Step 5, start here)
  Prophet — primary forecasting (Step 4); show confidence intervals
  XGBoost — optional later if you have rich features (not required for MVP)

VISUALIZATION
  plotly — interactive charts (primary)
  matplotlib — only if needed for static report assets

AI / LLM
  OpenAI API (GPT-4o or latest stable) — structured outputs / JSON mode
  Agent pattern: OpenAI tool calling OR LangGraph (pick ONE orchestration layer)
  Do NOT use both LangChain and LlamaIndex — unnecessary overlap for this project

DATABASE
  SQLite + SQLAlchemy — sessions, upload metadata, saved summaries (Step 1–6)
  PostgreSQL — when you deploy multi-user / real auth (Step 8)

VECTOR DB (PHASE D / PDFs only)
  ChromaDB (local, free, portfolio-friendly)
  Pinecone — only if you need managed cloud scale

REPORTS
  Jinja2 HTML templates → WeasyPrint or Playwright PDF (Step 6)

TESTING & QUALITY
  pytest — analytics unit tests (high ROI)
  ruff + mypy (optional) — lint/typecheck for senior feel

DEVOPS (WHEN DEPLOYING)
  Docker Compose: FastAPI + Next.js + Postgres
  Render / Railway / Fly.io — reasonable free tiers for portfolio


================================================================================
DATA CONTRACT (MVP — DEFINE IN README + SAMPLE FILE)
================================================================================

Canonical monthly P&L CSV (minimum):

  date          (YYYY-MM-DD or YYYY-MM, parsed consistently)
  revenue       (numeric)
  cogs          (numeric, optional → gross profit derived)
  opex          (numeric, optional)
  category      (string, optional — for expense breakdown)

Derived metrics (always computed in code, never guessed by LLM):

  gross_profit, net_profit (or operating_profit), gross_margin, opex_ratio
  MoM revenue growth, MoM profit growth
  top expense categories, rolling 3-month averages

Golden demo datasets (keep 2–3 fixed files in repo):
  1. Retail / sales monthly P&L
  2. SaaS-style revenue + opex
  3. Expense ledger with categories

Golden Q&A (regression-test prompts after changes):
  "Why did profits drop in March?" → must reference March metrics in CONTEXT
  "Which month performed best?" → must name month + revenue/profit figure


================================================================================
SYSTEM FLOW
================================================================================

Step 1 — Upload
  CSV / XLSX → validate (pydantic) → preview table → reject or continue

Step 2 — Data processing
  Clean: missing values, dates, currency symbols, (1,234.56) negatives
  Normalize column names (mapping UI later; MVP: fixed template)

Step 3 — Analytics engine (deterministic)
  KPIs, monthly trends, MoM growth, top expenses, metric snapshot JSON

Step 4 — LLM intelligence
  Input: metric snapshot + optional user question
  Output: executive summary, risks, opportunities, recommendations
  Each bullet links to a metric key (explainability)

Step 5 — Dashboard / UI
  KPI cards, plotly charts, AI insight panel, chat sidebar

Step 6+ — Forecast, anomalies, reports, auth (see build order)


================================================================================
BUILD ORDER (FOLLOW THIS — ORDER MATTERS)
================================================================================

STEP 0 — BEFORE CODE (1–2 days)
  [ ] One-page PRD: persona, primary use case, success criteria for Step 1
  [ ] Sketch 3 screens: upload+validation, dashboard, chat/summary
  [ ] List 10 KPIs you will always compute
  [ ] Draft system prompt template (JSON metrics in, narrative out)
  [ ] Choose: Streamlit-only Steps 1–2, add FastAPI at Step 3

-------------------------------------------------------------------------------

STEP 1 — DATA UPLOAD + DASHBOARD (NO AI)
  Goal: User uploads sample CSV → validated → dashboard appears.

  Build:
    - File upload (CSV, XLSX)
    - pydantic schema validation + error panel
    - Data cleaning pipeline
    - KPI cards (revenue, profit, margin, MoM %)
    - plotly: revenue chart, profit chart, top expenses, monthly trends
    - Minimal design from day 1: layout, typography, one chart theme
      (do not wait until Step 6 for basic polish)

  Skills shown: data analysis, dashboarding, product thinking, testing

-------------------------------------------------------------------------------

STEP 1.5 — DATA CONTRACT & SAMPLE TEMPLATE
  Build:
    - datasets/sample/ with 2–3 realistic files
    - README section: required columns, download sample, load demo data button
    - pytest tests for KPI functions on sample data

-------------------------------------------------------------------------------

STEP 2 — AI FINANCIAL SUMMARIES (METRICS-BACKED)
  Goal: Executive summary that only cites computed numbers.

  Build:
    - metrics_snapshot.json generated after analytics run
    - Metrics-only card in UI (numbers user can verify before reading AI text)
    - LLM call with structured CONTEXT + strict system prompt
    - Output sections: summary | trends | risks | opportunities | recommendations

  Example user action: "Generate executive summary"

  Skills shown: LLM integration, structured prompts, trust design

-------------------------------------------------------------------------------

STEP 3 — CONVERSATIONAL CHAT (TOOL-BASED AGENT)
  Goal: Answer questions with charts + cited metrics.

  Build:
    - FastAPI service (optional but recommended): sessions, chat history
    - Tools: get_kpi, compare_months, top_expenses, list_anomalies (stub ok)
    - Streamlit chat UI calling API OR embedded agent
    - Each answer: short narrative + optional chart + "Sources: metric X, period Y"

  Example questions:
    "Why did sales drop?"
    "Which month performed best?"
    "What drove the increase in opex?"

  NOT generic RAG over raw CSV rows — use tools on DataFrame / metrics store.

  Skills shown: agents, APIs, session design

-------------------------------------------------------------------------------

STEP 4 — FORECASTING
  Goal: Credible forward view with uncertainty.

  Build:
    - Prophet on revenue (and optionally opex) — primary model
    - UI: forecast chart + confidence band + 1-quarter / 1-year horizon toggle
    - LLM explains forecast using model output JSON (not invented numbers)

  Defer: XGBoost, ARIMA unless you need them for a specific dataset story.

  Skills shown: time series, communicating uncertainty

-------------------------------------------------------------------------------

STEP 5 — ANOMALY DETECTION
  Goal: Flag unusual months/spend; explain in plain language.

  Build:
    - Phase 1: z-score / IQR on monthly aggregates (fast, interpretable)
    - Phase 2: Isolation Forest on feature matrix (multi-variate)
    - Dashboard markers on charts + chat tool list_anomalies

  Detect: unusual spending, revenue drops, suspicious patterns

  Skills shown: unsupervised ML, business alerting

-------------------------------------------------------------------------------

STEP 6 — EXECUTIVE REPORTS & EXPLAINABILITY
  Goal: Deliverable a "executive" could forward.

  Build:
    - HTML report template (KPIs, charts as images, AI summary, disclaimers)
    - Export PDF + optional Markdown
    - "Why" panel: every insight → metric name, value, period, formula hint

  Skills shown: product value, document generation

-------------------------------------------------------------------------------

STEP 7 — MAKE IT BEAUTIFUL + SAAS FEEL
  Goal: Trust at first glance.

  Streamlit polish:
    - Dark/light theme, KPI cards, consistent plotly theme, branding

  Next.js upgrade (worth it for portfolio climax):
    - Rebuild main screens in Next.js → FastAPI backend
    - Upload history, saved reports (SQLite/Postgres)
    - Demo auth (simple session or Clerk/Auth.js) — even demo-only counts

  Skills shown: full-stack, UX, perceived enterprise quality

-------------------------------------------------------------------------------

STEP 8 — DEPLOY & HARDEN (FULL PROJECT FINISH)
  Build:
    - Docker Compose, env vars, README deploy section
    - PostgreSQL if multi-user
    - Rate limits on LLM endpoints, file size caps
    - ChromaDB + PDF ingestion (Phase D) if time allows

  Skills shown: shipping, security basics, DevOps awareness


================================================================================
SENIOR-LEVEL DIFFERENTIATORS (BUILD INTO STEPS 2–6)
================================================================================

1. AI RECOMMENDATIONS (metric-tied)
   "Marketing expenses increased 35% MoM while revenue grew 2%."
   → 35% and 2% must exist in metrics_snapshot.

2. EXPLAINABILITY
   Don't only predict — show WHY (metric + period + comparison).

3. EXECUTIVE REPORTS
   Downloadable PDF/HTML — huge perceived value (Step 6).

4. SESSION HISTORY (SaaS feel without full auth)
   Last N uploads, saved summaries, re-open dashboard — SQLite is enough for demo.
   Real login/auth in Step 8 if deploying publicly.
